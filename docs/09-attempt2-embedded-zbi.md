# 09 — Attempt 2: self-contained shim with an embedded ZBI

Attempt 1 ([08](08-flashing-lagos.md)) flashed `boot_a = shim(kernel) + ZBI(ramdisk)` and
**bootlooped**: LK ran (Moto logo) but the shim never got a clean ZBI. Root cause (confirmed
by analysis, not UART): on this GKI/MediaTek device the bootloader hands the kernel an
**initrd that is the concatenation of `init_boot` + `vendor_boot` ramdisks**, not our lone
ZBI — so the shim's default "boot the initrd as a ZBI" path sees garbage and aborts.
(`userdata` is irrelevant: the failure is pre-filesystem, at the kernel/shim handoff.)

## The fix: embed the ZBI inside the shim

The Fuchsia devicetree boot shim can get its boot ZBI three ways, selected by the
`zbi.boot` property (`zircon/kernel/phys/boot-shim/devicetree.cc`,
`GetDevicetreeBootZbi`):

| `zbi.boot` | source |
|---|---|
| *(empty)* | the bootloader initrd (`gDevicetreeBoot.ramdisk`) — **what attempt 1 used, broke on GKI** |
| `ramdisk:<name>` | a named entry inside the initrd (cpio or ZBI) |
| **`embed:<name>`** | **an image compiled into the shim binary** (`GetLinuxbootEmbeddedImage()`) |

With `embed:`, the shim **ignores the bootloader initrd entirely** and boots a ZBI that was
packed into the shim at build time — so the GKI ramdisk concatenation can't corrupt it. If
the embedded blob is a raw ZBI, it's used directly (the name after `embed:` is ignored).

### What we changed

1. **`zircon/kernel/arch/arm64/phys/boot-shim/linux-arm64-boot-shim.cc`** — force embed mode
   before `Boot()`:
   ```cpp
   ZX_ASSERT(shim_helper.InitItems());
   shim_helper.set_zbi_boot("embed:zbi");   // <-- fuchsia-lagos
   shim_helper.Boot();
   ```
   (`set_zbi_boot()` is the documented override; devicetree.h.)
2. **Pack** the rebuilt shim with our ZBI using the in-tree tool:
   ```bash
   python3 fuchsia/zircon/kernel/phys/linuxboot-embed.py \
     --output lagos-shim-embedded.bin \
     --shim  .../kernel.phys_arm64/linux-arm64-boot-shim.bin \
     .../product_bundle.arm64/product_bundle/system_a/fuchsia.zbi
   ```
3. **Wrap** the packed image as the boot kernel (ramdisk now irrelevant):
   ```bash
   mkbootimg --header_version 4 --kernel lagos-shim-embedded.bin --out lagos-fuchsia-boot.img
   ```
   (Regenerated by `tools/build-boot-img.sh`, which now packs the embedded shim.)

Result: a single self-contained `boot_a` image. The DTB (for the UART/memory/GIC) still
comes from the bootloader in x0 — which is fine, since the stock MediaTek DTB has the
`mediatek,mt6577-uart` node our relaxed `dw8250` accepts ([07](07-lagos-board-plan.md)).

## Attempt 2 RESULT (2026-10-28): still bootloops

Flashed the embedded image to `boot_a`, rebooted. USB sampling showed the MediaTek
preloader (`0e8d:2000`) **cycling** (preloader → quiet → preloader, ~20 s period) = still
bootlooping; screen cycled Moto-logo → black → reboot. Recovered TrebleDroid via antumbra.

**What this rules in/out:** the embedded ZBI removes the GKI-ramdisk variable, so that was
**not** (or not the only) cause. The failure is now pinned to **early boot, before the ZBI
is even loaded** — so the shim is faulting or being reset almost immediately. Leading
suspects, in order:

1. **MediaTek boot watchdog.** The ~20 s reboot period strongly fits a hardware watchdog
   that resets the AP unless the kernel services/disables it. Zircon bringup doesn't know
   MediaTek's WDT. Fuchsia's shim *does* have a `WatchdogMmioHelper` (devicetree.h) driven
   from a DTB watchdog node — but only if it recognizes the MediaTek `mediatek,mt6xxx-wdt`
   compatible/þlayout. **Prime suspect.**
2. **DTB parse.** The shim parses the stock MediaTek DTB (x0) — hundreds of nodes, 4-cell
   GIC/timer interrupts. Its memory/chosen/GIC matchers may choke → abort → reboot.
3. **LK→shim handoff / MMU** (`enable_mmu=true`, `generate_peripheral_ranges=true`) vs
   MediaTek's memory map.

**All three need the UART serial console to tell apart** — blind flashing only repeats
bootloop→recover with no new signal. Attempt 3 is gated on physical UART access
([08](08-flashing-lagos.md), "Physical UART"). When serial is available, first confirm the
shim even prints, then read exactly where it dies.

### Ideas for attempt 3 (once UART is wired)
- If watchdog: find the MediaTek WDT base in the stock DTB, confirm the shim's watchdog
  matcher binds it (or add the `mediatek` WDT compatible), or disable the WDT in the preloader.
- If DTB parse: feed the shim our clean `lagos-min.dtb` instead of LK's (embed a DTB in the
  shim, mirroring the embedded-ZBI change, or replace the `vendor_boot` DTB).
